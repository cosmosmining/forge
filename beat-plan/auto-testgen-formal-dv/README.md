# Forge feature 8 — auto test-case generation + formal DV

`forge_testgen` takes one RTL block, a short spec and a golden (integer) model, and:

1. **generates tests**: directed corners, pairwise combinations, vector patterns
   (ties, one-hot, ramps), constrained-random vectors, and for valid/ready blocks five
   protocol scenarios (back-to-back, long backpressure, ready toggling, sparse valid,
   random mix);
2. **runs them** on the RTL (Icarus Verilog by default, Verilator optional) with
   self-checking testbenches, and re-checks every output in Python;
3. **measures and closes coverage**: input/output corner bins, golden `cover()`
   events, *decision-boundary* bins derived automatically from every comparison,
   clamp, saturation, min and max in the golden, and protocol bins. Holes are closed
   by asking the solver for a witness vector; bins the solver proves unreachable are
   excluded with the proof named; golden-guided search covers the rest;
4. **proves properties formally** with SymbiYosys: full equivalence against the golden
   for combinational blocks; for valid/ready blocks, quiet-after-reset, hold under
   backpressure, no output without input, capacity, bounded latency and per-transaction
   equivalence against the golden (symbolic tracking), plus cover properties;
5. **injects bugs** (mutation testing) to measure what the tests and proofs catch, and
   separates real escapes from mutants that are provably equivalent.

Results: [RESULTS.md](RESULTS.md) (generated by the tool). How this connects to formal
tool #4, conformance pack #5 and the Build 6 blocks: [INTEGRATION.md](INTEGRATION.md).
Agent instructions: [skill/SKILL.md](skill/SKILL.md).

## Quick start

```bash
cd beat-plan/auto-testgen-formal-dv
python3 -m forge_testgen check  fixtures/specs/requant.toml   # spec vs RTL + golden translation
python3 -m forge_testgen run    fixtures/specs/requant.toml   # tests, coverage, formal -> runs/requant/report.json
python3 -m forge_testgen mutate fixtures/specs/requant.toml   # bug injection -> runs/requant/mutation.json
python3 -m forge_testgen all fixtures/specs/*.toml            # all of the above + 5 extra seeds + RESULTS.md
python3 -m unittest discover -s tests -v                      # tool self-tests
```

Requirements: Python 3.9+ (stdlib only; TOML specs need 3.11+ or `tomli`, JSON specs
work anywhere) and the open-source OSS CAD Suite on `PATH`: `yosys`, `sby`,
`yosys-smtbmc`, `yosys-abc`, `iverilog`/`vvp` or `verilator`, `bitwuzla`. In this
session the same open-source tools were installed from the Nix binary cache because
the OSS CAD Suite download host (github.com) was blocked by the session's network
policy; versions are recorded in every `report.json`.

## Flow

```
spec.toml ──► spec ↔ RTL port check (yosys) ─────────────── mismatch → SPEC-ERROR
golden.py ──► translate to Verilog reference ── self-check on every vector → TOOL-ERROR
                     │
     directed + pairwise + patterns + constrained random (+ protocol scenarios)
                     │
     coverage: data · golden cover() · decision boundaries · protocol
                     │ holes
     sby cover on golden+constraints ─► witness vector | proven unreachable (excluded)
     golden-guided search for anything still open
                     │
     simulate (TB compares; Python re-checks dumped outputs) ─────────► FAIL
     formal (comb: equivalence; stream: protocol + data + covers)
          counterexample ─► replayed in simulation ─► confirmed → FAIL
                     │
                   PASS (formal PROVEN or BOUNDED(n), stated as such)
```

## Spec format (TOML; JSON with the same keys also works)

```toml
[block]
name   = "requant"
top    = "requant"                       # RTL top module
kind   = "comb"                          # comb | stream
rtl    = ["../rtl/requant.v"]            # paths relative to the spec file
golden = "../golden/requant.py:requant"  # file:function

[[input]]                                # one per input field, in order
name   = "acc"                           # golden argument name
port   = "acc"                           # RTL port (default = name)
width  = 32
signed = true
count  = 1                               # >1: vector packed into one port, element 0 at LSB
range  = [-100000, 100000]               # optional legal range (default: full type range)

[[output]]
name = "y"
width = 8
signed = true

[constraints]                            # optional, golden-DSL expressions over inputs
expr = ["shift >= 1 or zp == 0"]

[coverage]
auto = true                              # input/output corner bins (default on)
[coverage.bins]                          # optional named bins over inputs + outputs
zero_out = "y == 0 and acc != 0"

[[directed]]                             # optional extra directed vectors
acc = -1
shift = 31

[gen]
random = 2000                            # random vectors (transactions for streams)
closure_budget = 5000                    # golden-guided search tries per open bin

[stream]                                 # kind = "stream" only
clk = "clk"
rst = "rst"
rst_active = "high"                      # or "low"
in_valid = "in_valid"
in_ready = "in_ready"                    # omit if the block is always ready
out_valid = "out_valid"
out_ready = "out_ready"                  # omit if the block cannot be stalled
capacity = 2                             # max transactions in flight (formal checks <=)
max_latency = 3                          # cycles with out_ready high and work in flight
                                         # before an output must appear

[formal]
depth = 16                               # BMC depth for stream blocks
prove_timeout = 300                      # seconds per solver job
```

A stream block's golden maps one input transaction to one output transaction, in order.

## Golden DSL

Golden models are ordinary Python functions over Python ints, so they run as the
simulation oracle directly. The same source is translated into a bit-exact Verilog
reference for the formal checks: every intermediate value gets an exact integer
interval and a signed wire wide enough for it. Supported:

- statements: `x = e`, `a, b = e1, e2`, `x += e` (and other augmented ops),
  `for i in range(const)` / `for v in some_list` (unrolled), `if/elif/else` on data
  (merged into multiplexers), `cover("name", cond)`, `return {...}` as the last statement;
- expressions: `+ - * << >> & | ^ ~`, `//` and `%` by power-of-two constants, `not and or`,
  comparisons (chains allowed; `==`/`!=` also on lists), `a if c else b`, list literals,
  comprehensions and indexing (constant or data-dependent), `min max abs sum len int bool`;
- helpers from `forge_testgen/golden_lib.py`: `clamp(x, lo, hi)`, `sat(x, width, signed=True)`,
  `wrap(x, width, signed=True)`, `rshift_round(x, s)` (round half up), `cover(name, cond)`;
- helper functions defined in the same file (inlined) and module-level int constants.

Anything else is rejected with a file:line message rather than mistranslated.
`tests/test_golden.py` checks Python == translated graph == Icarus simulation of the
emitted Verilog on thousands of vectors per construct.

## Coverage model

| kind | bins | measured on |
|---|---|---|
| data | each input element at min / max / zero (if in range), each output at its type min / max / zero; vectors: all-equal, tie at max; spec `[coverage.bins]` | generated vectors + golden outputs |
| golden | every `cover("name", cond)` in the golden | golden execution |
| boundary | for every comparison / clamp / sat / min / max / abs the golden evaluates: operand difference == -1, 0, +1, only while that code is on the executed path | translated golden |
| protocol | backpressure seen, input stall seen, back-to-back in/out, full occupancy | simulation monitors |

Boundary bins were added after the first bug-injection run on `requant` showed a
simulation escape (a saturation threshold off by one, visible only when the
pre-saturation value is exactly -129). `a_input_progress` and
`a_accepts_below_capacity` were added after the first run on `sfifo` showed formal
missing three deadlocking mutants and classing a FIFO that holds only 2-3 of its 4
entries as conformant. The earlier runs are kept in `runs/history/`.

## Formal properties (valid/ready blocks)

| label | meaning |
|---|---|
| `a_quiet_after_reset` | no `out_valid` in the first cycle after reset if no input is offered |
| `a_hold_valid`, `a_hold_data` | an output stalled by `!out_ready` stays valid and unchanged |
| `a_no_spurious_output` | every output handshake matches an accepted input |
| `a_capacity` | transactions in flight never exceed `capacity` |
| `a_bounded_latency` | with work in flight and `out_ready` high, an output appears within `max_latency` cycles |
| `a_input_progress` | with `out_ready` held high, an offered input is accepted within `max_stall` cycles (default `max_latency + capacity + 1`); catches blocks that deadlock or never accept |
| `a_accepts_below_capacity` | opt-in (`accepts_below_capacity = true`, for elastic buffers): an offered input is accepted whenever fewer than `capacity` transactions are in flight |
| `a_data_matches_golden` | any one accepted transaction (chosen by the solver) leaves with exactly the golden's output, in order |
| covers | an output occurs; the tracked transaction is checked; backpressure, input stall and full occupancy are reachable |

Environment assumptions: reset in the first cycle; upstream holds `in_valid` and data
until accepted; offered data satisfies the spec constraints. The data check applies the
golden to the input in the cycle it is accepted and stores the expected output, so the
solver compares the RTL and the golden on the same input variables.

Verdicts: `PROVEN` (unbounded: complete miter, k-induction or PDR), `BOUNDED(n)` (no
counterexample in n cycles from reset — not a proof), `FAIL` (counterexample, replayed
in simulation), `UNKNOWN` (solver gave up).

## Guards against false results

- spec ports, widths and directions are compared with the RTL before anything runs;
- the translated golden is re-checked against the Python golden on every generated vector;
- the testbench compares in simulation and Python re-checks the dumped outputs;
- a formal counterexample counts only after it replays in simulation;
- coverage-witness vectors are re-checked with the Python golden before use;
- mutants that survive are checked against the original RTL with a formal miter, so
  equivalent mutants are excluded instead of being reported as test escapes.

## Limitations (current)

- Stream blocks must map one input transaction to one output transaction. Packet or
  reduction-over-a-stream blocks (k inputs -> 1 output) are not supported yet.
- Formal data proofs through multiplier pipelines may end `BOUNDED(n)` rather than
  `PROVEN` (PDR runs out of time); this is reported, never upgraded.
- Formal uses Yosys' two-valued model: X-propagation (e.g. an out-of-range memory read)
  is invisible to it. Simulation compares with `!==` and catches X; this is one reason
  both engines always run.
- RTL is read with Yosys' built-in Verilog/SystemVerilog frontend; designs using SV
  features it lacks (interfaces, packages, classes) need the yosys-slang plugin.
- Mutation operators are source-level and single-point; they model common coding
  bugs, not every possible fault.
