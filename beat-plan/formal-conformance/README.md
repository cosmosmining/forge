# Feature 7: formal verification + conformance pack

**Status, 28 Nov 2026.** Both tools are built and checked in this checkout. **No Forge block
has been checked yet**: this checkout of `cosmosmining/forge` holds only the public landing
page, with no engine RTL and no proof outputs. Every result below is on **stand-in blocks**:
RTL generated by the Amaranth HDL standard library, used only to exercise the tools. None of
it was hand-written. These results say nothing about Forge hardware.

The existing formal property library (#4) and the 64-file conformance pack (#5) are also not
in this checkout, so this is a standalone extension built to sit next to them. See
"Merging" below.

## Verdicts (Forge gate semantics: PASS, FAIL, INCOMPLETE; only PASS counts)

| Verdict | When |
|---|---|
| **PASS** | Structure clean (no latches, `check -assert` clean). Every assertion proven by k-induction. Every cover reached, each with its own "reached" line in the log |
| **FAIL** | A structural problem, a counterexample (trace kept as evidence), or a cover not reached within the cover depth. In that last case the proof may be vacuous |
| **INCOMPLETE** | Tool error or timeout, induction did not converge (a bounded result is never reported as PASS), or the spec has no assertions or no covers |

The tests show the gate can say no:
- a wrong bound gives FAIL with a counterexample at step 4 or later;
- an impossible cover gives FAIL;
- a spec with no covers gives INCOMPLETE;
- dropping the induction helpers gives INCOMPLETE, because the ordering property is not
  inductive on its own.

## Mutation analysis

`mutate` asks yosys (`mutate -list`) for N mutants of the block, then checks each with sby
bmc against the **contract** properties only. Induction helpers are excluded: they describe
the original design's internals.

- A survivor is put through yosys' own equivalence flow (`equiv_make`, `equiv_induct`).
  Only a proof moves it to "equivalent".
- A survivor without that proof counts against the score.
- Kill rate = killed / (killed + survived).
- "Survived" means no contract violation within the bmc depth, so it is a bounded statement.

## Conformance pack rules

The pack records what evidence files already say. Per claim it keeps:
- the values, each read by a JSON pointer;
- the kind (measured, derived, model, not-yet);
- the SHA-256 of the evidence file and of every file that evidence lists (chain of custody).

A claim is **not recorded**, with its reason listed, when:
- no evidence file is named or found;
- a requirement fails;
- a bit-exact claim lacks a zero mismatch count together with either compared > 0 or a
  "proven" status (a claim cannot relax this);
- a derived value does not recompute from recorded inputs (the formula may only use
  `+ - * /`);
- a model number lists no assumptions;
- a not-yet claim carries a number.

The pack is deterministic: the same inputs give the same manifest hash. Building and
verifying it start no process; a test enforces that.

## Using it on Forge blocks after the merge

```bash
python3 formal/forge_formal.py discover ../../<rtl dir> --out results/discover.json --skeletons formal/specs/drafts
# write formal/specs/<block>.json: contract properties with their source, covers, mutation settings
python3 formal/forge_formal.py run formal/specs/<block>.json
python3 formal/forge_formal.py mutate formal/specs/<block>.json
python3 formal/forge_formal.py summarize
# add claims pointing at results/<block>/verdict.json, or at the Qwen proof JSON, then:
python3 conformance/forge_conformance.py build && python3 conformance/forge_conformance.py verify
```

Spec fields:

| Field | Meaning |
|---|---|
| `rtl` | RTL file paths |
| `instances` | Each instance: `module`, optional `connect` (drive an input from an expression), `expose` and `expose_prep` (yosys commands that turn internal signals into ports, for induction helpers) |
| `clock`, `reset` | Clock port; reset port with polarity and init cycles |
| `free_inputs`, `anyconst`, `helper_sv` | Free harness inputs, solver-chosen constants, and tracker logic |
| `properties` | `assert`, `assume`, `assert_next`, `assert_after_reset`, `stream_out`, `stream_in`, each with a `role` and a `source` |
| `covers` | Reachability targets for non-vacuity |
| `bit_exact` | The bit-exact claim the spec supports |
| `mutation` | Mutation settings |

Expressions use `inst.port`, or bare port names when the spec has a single instance.

## Limits and open items

- **No Forge block checked.** The claim `forge.blocks.formal` is recorded as not-yet.
- The 4 Forge bit-exact and gate claims from the public page stay not recorded until their
  evidence JSON is added (`claims.json` says what each needs).
- The frontend is yosys `read_verilog -sv`. Engine RTL that needs SV packages or
  interfaces needs `"frontend"` pointed at a fuller SV reader (yosys-slang or sv2v).
- The unbounded engine is k-induction only (see `TOOLCHAIN.md`). Deep pipelines may need
  helper invariants, as the FIFO did.
- The mutation equivalence check is incomplete by nature. Unproven survivors are counted
  against the score.
